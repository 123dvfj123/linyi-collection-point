PRs targeting either branch still run all five jobs. Both Docker timeout

| Event | Expected CI after this patch |
|---|---|
| Push to main or develop | Full workflow |
| Push to a working branch without a PR | No CI |
| Push to a working branch with a PR to main/develop | PR synchronization runs CI; no additional push run |
| PR opened, synchronized or reopened against main/develop | Full workflow |
| PR targeting another working branch | No CI from this workflow |

The trade-off applies to every job, including backend, frontend and commitlint.
A contributor without hooks is checked when a qualifying PR is opened or updated,
but receives no automated checks on an isolated branch push. Open the PR promptly.

**What v0.2.0 contains.** Parcel registration and batch intake (`T-42-01`), storage
location management with the four states and manual override limited to `available`
and `disabled` (`T-42-03`), pickup-code verification and handover with idempotent
confirmation (`T-42-04`), the frontend wired to the real API (`T-42-09`), the audit
log with phone masking (`T-41-03`), authentication with four-role access control
(`T-41-01`), the Flyway baseline and the five-job CI, and the contract vocabulary of
`CR-031` extended to thirteen codes by `CR-033`.

**What v0.2.0 does not contain, and why.**

- **No path from `registered` to `shelved` *at the released commit* `3300a84`.**
  `Parcel.register` sets `registered` unconditionally and `ParcelController` exposes
  only the two POST endpoints there, so the state machine's `registered → shelved`
  edge has no API. The integration tests reach `shelved` through their own fixtures.
  This is scenario 1 of issue #239.
  **It also blocks the fourth line of `#185`'s definition of done** — "a staff member
  can record a parcel, choose a storage location by hand, and hand the parcel over".
  Two of those three steps work through the API: `POST /api/parcels` records the
  parcel and accepts a `locationId`. The third does not, because `Parcel.collect`
  rejects anything that is not `shelved`, and nothing sets `shelved`. The handover
  therefore cannot be demonstrated end to end through the running application at
  `3300a84`; the Testcontainers tests demonstrate it against a fixture that writes
  `shelved` directly. **`CR-029` settled the schema question and left the operation
  unbuilt.**
  **This is being fixed in pull request #271**, which adds
  `PATCH /api/parcels/{id}/location` and moves the parcel and the location together
  in one transaction. `#271` is not part of `v0.2.0`; the tag stays at `3300a84` so it
  marks the commit Sprint 2 actually closed on.
- **No backend route for four of the fourteen paths in `openapi.yaml`.** `GET /my-parcels`,
  `GET /my-parcels/{id}` and `GET /my-parcels/{id}/pickup-code` are the resident read path
  `CR-013` added to the Sprint 2 contract; `PATCH /parcels/{id}/status` is the state-machine
  edge with optimistic locking. None of the four has a controller method, and the two
  resident pages are static placeholders. The contract now marks each one as specified and
  not built, in the same words it already used for `/locations/recommend`.
- **No real-stack journey verification.** Only the Testcontainers tests exercise
  intake, storage, pickup and handover end to end.
- **The batch-handover endpoint is absent by design** (`CR-031`).
- **`T-42-02`, the location recommender, is deferred** (`CR-023`).

**The tag and `#185`'s definition of done.** The definition of done asks for
